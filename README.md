## 보스 등장 규칙 — 오염도 단계별 (2026-10-14 사용자 재확정)

**보스 출현 기준은 바퀴 수가 아니라 오염도**다. 오염도 **20 → 1단계 보스, 40 → 2단계 보스, 60 → 3단계 보스**, 이후 **최종 보스**가 별도로 등장하는 것이 확정된 기획이다. 최종 보스가 나오는 정확한 오염도 수치와 단계별 보스 처치·재출현 조건은 아직 확정되지 않았다. 임의로 80/100을 대입하거나, 세 보스를 동일한 보스의 매 바퀴 반복 등장으로 해석하지 말 것.

**현행 구현과 기획은 다르다.** `systems/map_state.gd`는 현재 `BOSS_CONTAMINATION = 20` 기준으로 하나의 `boss` 타일을 배치하며, 오염도 40/60별 다른 보스와 최종 보스 단계 구분은 구현되지 않았다. 완주 후 집에서 나갈 때 오염도 **+7**은 오염도 증가 규칙이지 직접적인 보스 발생 회차 조건이 아니다. 구현 간극과 남은 결정을 [맵 이식·보스 규칙](docs/map_port.md)에 기록한다.

## 타일 해금 기획 — 사건 우선, 빈 사건에서 장소 발견 (2026-10-14)

**기존 메인 사건은 항상 우선 진행**한다. 해당 조건의 메인 사건이 없는 실제 사건 타일 방문에서는 **미발견이고 장소별 해금 조건도 충족한 장소**에 한해서 발견 후보가 생긴다(예: "언덕을 발견했다."). 조건 충족 장소가 있으면 장소 발견 또는 **반복 가능한 루틴 사건** 중 하나가 나오고, 조건 충족 장소가 없으면 루틴 사건이 나온다. 예: "쓰러진 병사를 도왔다. 주사위 제어 카드 1장을 받았다." 루틴 사건은 현재 획득 기회가 부족한 소모형 주사위 제어 카드의 추가 획득처다. 발견한 장소는 집에서 편성해 다음 맵에 반영하는 방식을 권장한다. 보유 상한 5장과 교체/포기를 유지한다. **현재는 신규 기획이며 실제 게임 코드에 아직 구현되지 않았다.** 기존 언덕 시작 배치·묘지 첫 바퀴 자동 등장·숙영의 집 해금과 충돌하는 규칙은 통합 변경이 필요하다. [타일 발견 기획](docs/event_tile_unlock_design.md) · [장소별 발견 조건 제안](docs/location_unlock_conditions.md) · [루틴 사건 및 카드 공급 설계](docs/routine_event_design.md).

## 현재 개발 방식 — 2026-10-10

- 공개 Godot 원본: https://github.com/gamja121/necromancer-and-dice-godot

- PC에서 구현·검증한 작업을 commit/push하여 공개 main과 동기화한다. 연결된 GPT/Codex는 이 저장소의 원본을 확인하고 권한이 있으면 수정한다.

- 이식 상태 및 남은 범위: [docs/godot_port_status.md](docs/godot_port_status.md)

## 실행

Godot에서 project.godot을 열고 F5로 실행한다. 기본 시작 장면은 project.godot의 application/run/main_scene 설정을 따른다.
독립 전장을 확인하려면 battlefield.tscn을 열고 F6로 실행한다.
Windows의 launch_game.cmd는 로컬 엔진 설치 경로에 맞춰 수정해서 사용한다.
