# 언덕 경로 선택 UI — 2026-10-28

사용자가 승인한 실제 원화 구상안을 적용한다. 언덕에 들어오면 한 화면에서 앞으로 1~6칸의 실제 지도 타일을 고르고, 공용 ‘여기로 이동’ 버튼으로 확정한다. 기존 나무/밤하늘 원화와 타일 그림은 변경하지 않는다.

- Trigger: 기존 이야기 도착 우선순위 이후의 일반 언덕 기능 화면. 단순 미리보기만으로 이동하거나 신규 정보를 추첨하지 않는다.
- Information: 실제 앞칸의 거리·타일명·그림, 선택 후 실제 번호를 표시한다. 긴 장소 이름은 두 줄로 감싼다. 집 도착은 허용하고 집을 넘어가는 선택은 흐리게 잠근다.
- Interaction: 미선택 확정 금지, 선택은 미리보기만, 한 번 나가기로 보드 복귀. 현재 언덕·미사용 방문·활동 중인 전투/보상/이동 없음이라는 기존 사용 조건을 반영한다. NEW 표시는 실제 확정 때 확인한다.
- Visual: 승인된 작은 타일 경로, 얇은 먹선, 선택 타일 1.16배 확대와 깃발. 예언자/공동묘지의 공용 창 `(340,423,600,150)`과 map 공통 action/exit RECT, variant04 원본 버튼을 사용한다. 성공 저장 후 같은 화면의 확정 양피지를 기존 소진 연출로 떼고 원래 말 이동을 실행한다.
- Memory: `RunSession.prepare_hill_move`, 저장 형식, 주사위/카드/RNG, 방문 영수증과 기존 워프·늪·집·이야기 도착 처리는 변경하지 않는다. 이동 전 영수증을 보관해 move_serial 증가 후에도 정확한 버튼을 소진한다. 저장 실패 때 같은 선택과 화면에서 이유를 보여주고 재시도할 수 있다. 이동 중 종료하면 기존 pending_move 복원으로 이어간다.

새 `hill_route_picker.gd`는 화면만 그린다. 세계 상태나 저장 API를 참조하지 않는다. 장소 overlay 정리는 기존 공동묘지에서 사용하던 보호를 두 화면에 공유하며, 새로운 overlay의 표시나 입력을 건드리지 않는다.

## 검증

Godot 4.7.2 Compatibility import와 집중 검사, 실제 GPU 캡처를 수행했다. 언덕 기존 검사 61개, 공용 배치 378개, 원본 버튼 소진 120개, 지도 도착 131개, 공동묘지 117개가 오류 없이 통과했다. 새 집중 검사는 선택/취소/NEW/저장 실패 재시도/집 경계/원격 언덕/보상 대기/이동 중 종료 후 재시작/긴 장소 이름을 검사한다. 테스트용 지도도 고정 앵커를 보존하며 정상 저장 schema로 복원되는지 검사한다.

실제 GPU 캡처 22개 검사를 통해 선택 전·4칸 선택·집 경계 화면을 1280×720으로 기록했고, 선택만으로 저장 파일과 RNG가 바뀌지 않음을 확인했다. CI에 집중 검사와 GPU 캡처를 추가했다. 기존 CI의 170초 import 제한은 이전 작업에서도 시간 초과가 확인돼 240초로 조정했으며 기능 검사 조건은 유지한다.

작업 #334. 원본 자산·개인 진행/설정·이야기/보상 코드는 변경하지 않는다.

통합 검사에서 발견한 임시 지도 구성도 보완했다. 원래 워프 칸에 테스트 언덕을 강제로 놓아도 두 워프를 보존하는 사례를 고정 재현하고, 각 임시 지도의 워프 쌍과 저장 스키마를 확인한다. 실제 게임 생성·이동 코드는 변경하지 않는다.

최신 공유 main의 희귀 몬스터/등급별 돌 변경(#336~338)을 보존해 합쳤다. 통합 후 언덕 기존 61, 집중 90, 자연 집 복귀 70, 돌 이동 43, 전체 진행 86, 희귀 돌 101 및 실제 GPU 22 검사가 오류 없이 통과했다. 서버 GPU 검사는 오디오 장치가 없는 환경을 명시하고, 화면의 지연 삭제가 끝난 뒤 비동기 자원 정리를 확인하도록 보완했다. 오류·누수 검사 조건은 유지한다. 로컬 project.godot의 엔진 생성 주석/정렬 차이는 기존 사용자 파일로 보존하며 이 작업에 포함하지 않는다.
