## 2. 검증된 스토리 흐름과 빠진 고리

`systems/ritual_portal_beats.gd`:
- 의식 광신도가 왕을 소환. 대결 성공은 **불완전 부활**, 실패는 **완전 부활**로 갈린다.
- 어느 분기든 마물의 왕은 현세에 나타난 뒤 어둠 속으로 사라지며, 독립된 얼굴/신체를 직접 노출하지 않는다.

`systems/monster_king_hunt_beats.gd`:
1. `arrival`: 세계수의 뿌리와 검은 흔적.
2. `trace`: 오염된 사체와 마물 사냥꾼.
3. `revival`: 사냥꾼이 왕의 불완전/완전 부활 흔적을 해석.
4. `destination`: 오염의 방향이 오래된 봉인 폐허로 향함을 확인.
5. `located`: **“숲속 봉인 폐허의 위치를 파악했다. 추적은 끝났지만 왕과의 싸움은 아직 시작되지 않았다.”**로 끝난다.

현재 `systems/final_boss_story_gate.gd`는 이 5번째 화면의 `마치기`까지 확인하고, 현행 `MapState`는 오염도 80과 결합해 보스 타일을 해금한다. `systems/run_session.gd`에서 그 보스 타일 전투 적으로 드래곤이 들어가지만, **봉인 폐허 도착 / 왕 직접 조우 / 대면 대사는 사이에 존재하지 않는다**.

## 3. 원화의 일관된 미술 언어

- **배경**: 극사실풍 다크 판타지 페인터리, 중세 석조 유적/숲/마을, 앞·중간·뒷경의 강한 깊이감, 그림 주변 금속성 금빛 장식 테두리. 본편 배경은 화면 가로세로 약 16:9를 전제로 한다.
- **명암**: 부활 의식은 차가운 남청색·보라색 광원과 검은 그림자, 평화로운 세계수는 햇빛·연한 초록·금색. 오염은 검보라색과 주변 오브젝트에 박힌 결정/가시.
- **인물/효과**: 배경 그림에 사람을 통째로 합쳐 새 프레임으로 교체하기보다 투명 인물/군상/마법 레이어를 별도로 얹는다. 레이어 자체의 검은 부분은 웹 미리보기 검정 배경이 아닌 투명도 성분을 유지한다.
- **UI**: `docs/story_split_ui_20261021.md`의 사용자 확정 구도. Godot `systems/story_split_layout.gd`는 1280×720의 왼쪽 그림 `Rect2(55,176,650,365.625)`, 오른쪽 서술·화자·버튼 패널. 기존 `story_modal()`과 명시적 `계속`/`마치기` 계약 유지.
- **등장**: `InkSceneReveal` 초기 배경 1회, 별도의 스프라이트 레이어는 이전 사냥꾼/전이문 CSS 이식의 짧은 진입 효과 패턴을 재사용. 과한 풀스크린 효과/카메라를 발명하지 않음.

## 4. 새로 필요한 원화 (기존 파일에 없음)

아래 파일명은 **제작 제안**, 저장소에서 확인된 현재 자산은 아니다.

1. `assets/map/events/monster-king-sealed-ruins-base.webp` — **독립 봉인 폐허 16:9 배경**. 세계수와 전이문을 따라온 오염의 흔적을 공간에서 연결하되, 기존 의식 전이문 배경을 ‘봉인 폐허’라고 이름만 바꿔 재사용하지 않는다. 테두리·원근·아래쪽 UI 공간은 기존 배경과 맞춘다.
2. `assets/map/events/monster-king-ruins-omen-layer.webp` — 폐허에 남은 검보라색 오염/불길한 움직임. 투명 레이어.
3. `assets/map/events/monster-king-presence-layer.webp` — 처음 조우하는 **왕의 실루엣**. 얼굴·종족·몸체를 임의 확정하지 않고 연출상 존재감만 보여줄 수 있게 분리.
4. `assets/map/events/monster-king-reveal-layer.webp` — **왕의 확정 원화는 아직 미제공/미승인**. 왕=최종 드래곤인지, 별도 존재인지 결정될 때 제작. 임의로 기존 문 속 인물을 왕의 초상이라 선언하지 않음.

기존 드래곤 책페이지/28프레임 준비는 별도 `PR #259`에 있으며 **이 네 그림이 이미 그 PR에 포함됐다고 주장하지 않는다**.

## 5. 다음 사건의 권장 5비트 기획 (제안·미확정)

| 비트 | 카메라/원화 | 이야기 기능 | 상태 |
| --- | --- | --- | --- |
| `arrival` | 새로운 봉인 폐허 전경 | 사냥꾼이 지목한 위치에 **실제 도착** | 제안 |
| `evidence` | 폐허 배경 + 오염 흔적 | 여기까지 이어진 왕의 흔적과 전이문 부활 분기의 결과를 연결 | 제안 |
| `presence` | 푸른·보랏빛 움직임 + 왕의 실루엣 | 전투에 앞서 존재를 **처음 인지** | 제안 |
| `confrontation` | 확정된 왕의 외형 레이어 | 왕과 **서로 마주하는 장면**. 발화 대사는 아직 없음 | 제안 |
| `ready` | 왕의 모습/폐허 전경 | 명시적 클릭 후 현재의 보스 전투/덱 선택 루트로 이행 | 제안 |

- 대사는 현재 원본에 없는 만큼 **확정된 사용자 대사로 쓰지 않는다**. 불완전·완전 부활 분기는 보존하고 신규 능력치·보상·전투 패턴·엔딩은 작성하지 않는다.
- 현행 본편은 `located` 완료와 오염도80 이상에서 보스 타일이 열린다. 다음 사건을 개발할 때는 **실제 보스 타일 착지 시점**을 후보로 하고 `show_tile()` → 원화 사건 → 보스 덱 선택 흐름을 테스트한다. 보스 타일을 보는 프리뷰/세이브 불러오기만으로 이야기가 진행되면 안 된다.
- 기존 저장 유저는 새 조우 이벤트 영수증이 없더라도 진행 이력을 소급 삭제하지 않아야 한다. 조우의 `seen`/`acknowledged` 상태를 하나의 원정 저장 트랜잭션으로 관리하고 실패 시 롤백.
- 왕과 드래곤의 정체 관계는 본 요청과 현재 원화만으로 단정할 수 없다. 조우의 보스 연계를 설계할 때 별도 합의가 필요하다.

## 6. 다섯 원칙 확인 (설계 단계)

- **Trigger**: 마지막 왕 추적 5번째 `마치기` 저장 후 정식 보스 타일에 **실제 착지**.
- **Information**: `final_boss_story_gate.gd`, `monster_king_hunt_entry.gd` 완료 영수증과 포털 승리/실패에 따른 부활 모드.
- **Interaction**: 우측 `계속` / 마지막 명시적 진행 / 기존 보스 편성 화면 재사용.
- **Visual**: 좌측 원화는 기존 16:9 + 어두운 금빛 프레임; 왕은 투명 레이어 독립 등장, 기존 대사창·버튼 배치 재사용.
- **Memory**: 장면별 승인·재개·저장 실패 복구; 중복 보상·두 번 재생·프리뷰 소모 금지. 드래곤 스탯·고유 28프레임 자산/세이브/전투 규칙 불변.

## 남은 일과 검증 경계

이 문서는 **원화 실사 검토 + 스토리 결손 확인 + 제작 명세 초안**을 완료한다. 실제 봉인 폐허/왕 원화의 PNG/WebP 제작, 왕 대사 확정, 게임 `map.gd` 연결, save migration, 테스트, PC 확인과 main 병합은 완료하지 않았다. 다른 진행 중 PR #259는 건드리지 않는다.
