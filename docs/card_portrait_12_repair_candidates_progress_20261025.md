# 마물카드 12종 · 누끼 먹선 보정 후보 제작 결과

**상태:** 1차 후보 12종 생성 및 GitHub Actions 검증 성공. **게임 본편 원화 교체 0종.**

## 범위
지옥 사마귀, 해골 기사, 데스 나이트, 해골 소환사, 역병술사, 고블린 족장, 전갈 기사, 살점 골렘, 숲의 장로, 거미 여왕, 암석 골렘, 고블린 라이더.

## 실제 작업
- 원본 그대로 사용한 `_safe.png` 보수적 후보, `_review.png` 확장 후보, `_review_mask.png` 비교 마스크를 각 12종씩 생성
- 복구 시도를 한 곳은 외부 배경과 연결되지 않은 투명 공간 중 검은 원화 경계로 둘러싸인 부분으로 한정
- 원본에서 알파 24 이상이었던 픽셀은 **RGB와 알파 모두 변경하지 않음**; 이미지 해상도 유지
- 자세한 상태표: `card_repair_candidates_12/status.csv` (GitHub Actions artifact)
- GitHub Actions `Priority 12 Card Ink Candidates`: **통과**

## 안전성과 현재 한계
- 누끼 전 원본은 GitHub 기존 버전과 연결된 Google Drive 에셋 폴더에서 찾지 못함. Drive의 `hell-mantis` 폴더는 비어 있었고 `skeleton-cavalry` 폴더는 전투 프레임이었음.
- 투명 부분 모두가 오류인 것은 아님. 갑옷 구멍·찢어진 옷·지팡이 고리 등 의도된 공간을 메울 수 있으므로 확장 후보를 바로 게임에 적용하지 말 것.
- 이 단계는 전수 분류 이후 '복구 후보 12종 제작' 단계이지, **검증된 최종 원화 12종 복원 완료가 아님.**
- 승인된 픽셀만 남긴 뒤 검은/밝은 배경과 실제 Godot 카드 표시 크기에서 QA 하고 원본 백업을 유지해 교체해야 함.

## 재현 방법
`python3 scripts/candidate_12_card_ink_alpha_recovery.py`
실행 시 `card_repair_candidates_12/`에 12종 후보·마스크·CSV 생성. 저장소 `assets/cards/layered`는 직접 수정하지 않음.
