# 전투 진입 성능 · 2026-10-08

환경: Godot 4.7.2 Compatibility, GTX 1660 Ti, 1600×900 창/1280×720 논리 화면.
프로젝트 밖 임시 진단으로 같은 초기 편성(아군 1, 적 1) 3회 진입. 비교 측정은 최대 60fps로 제한했고 맵 생성 후 1초 대기했다. 개인 저장은 원본 바이트로 복원했다.

| 측정 구간 | 변경 전 | 최종 |
| --- | --- | --- |
| 덱 선택창 setup | 56.51–61.21ms | 2.23–2.84ms |
| 첫 중앙 전투 setup | 275.13ms | 68.61ms |
| 다음 중앙 전투 setup | 255.08–264.35ms | 55.20–56.17ms |
| 전투 첫 draw 대기 | 9.61–10.38ms | 3.34–6.99ms |
| 전투 대기 p95 | 16.687–16.695ms | 16.696–16.844ms |

setup은 CPU 호출 구간이고 실제 사용자 입력부터 전환 완료까지의 전체 시간이 아니다. 기존 출발/진입 Tween 시간은 그대로 유지했다.
초기 이펙트 준비만 따로 측정했을 때 143–168ms였다. 런타임 이미지 절단과 GPU readback/업로드를 AtlasTexture 영역 및 여백 참조로 교체했다.
지도에서 한정된 공용 시트/음악/배경/보유 카드·첫 모션을 ResourceLoader threaded API로 미리 읽는다. 미완료 리소스에는 load_threaded_get을 호출하지 않으며 프레임당 결과 1개만 받아 UI 작업을 분산한다.
원본 효과 시트는 한정된 static cache로 유지한다. 모든 마물의 모든 프레임을 미리 올리지는 않는다.
임베디드 전투는 지도 한글 테마를 상속한다. standalone 전투는 기존 자체 폰트를 유지한다.
오디오 출력 장치 목록은 캐시하며 오디오 창을 열 때 갱신한다. 이미 선택된 동일 장치의 재선택을 피한다. NOX 출력·음량 설정은 유지했다.

## 검증 및 비용
- 기존 69개 효과 프레임의 영역·여백·크기·픽셀 동일 확인.
- 실제 GPU로 전체 타격 효과/피해·회복 숫자 표시 확인 및 전투 한 라운드 완료.
- 한글 폰트 상속 및 오디오 창 새 장치 목록 갱신 확인.
- 대기 프레임은 약 60fps. 3회 진입에서 메모리 증가가 누적되지 않았다.
- 보존 캐시로 텍스처 메모리가 약 58→120MiB, static memory 약 62→68MiB 증가했다. 이는 재로딩을 줄이기 위한 고정 비용이며 측정 3회 동안 안정적이었다.
- 전체 원정/긴 전투, 마물 4대4+, 모바일 실기기 및 더 느린 디스크 검증은 아직 수행하지 않았다.
- 첫 전투에는 약 69ms setup 지연이 남는다. 즉시 진입하면 비동기 준비가 덜 끝날 수 있다.
- 개인 저장 복원, 임시 진단 스크립트 제거. 게임 내 테스트/디버그 UI 추가 없음.

## 이후 성능 원칙
사건 원고 작업은 보류 상태다. 콘텐츠 추가 시 활성 장면 중심으로 로드하고 한꺼번에 모든 리소스를 생성하지 않는다.
다음 확인은 실제 4대4 전투와 첫 공격/영구사망/보상 전환 구간의 프레임 시간이다.
현재 짧은 측정만으로 완성본 성능이나 메모리 누수 부재를 보장하지 않는다.
