## 이식 작업 순서

### 2-A. 사건 기반부터 만든다 — 최우선

사건은 현재 코드와 에셋이 함께 비어 있어 가장 큰 공백이다.

작업 순서:
1. 사건 필수 원화/레이어를 Godot로 복사한다.
2. `event / quest / story` 상태 구조를 만든다.
3. 공동묘지 아이 사건과 선택을 연결한다.
4. **싸운다 선택은 반드시 현재 공용 덱 선택 화면을 거쳐야 한다.**
5. 사건 전투 종료 뒤 원래 사건으로 돌아오는 context를 만든다.
6. 덱 선택/전투/복귀 중 종료 후 이어하기를 지원한다.
7. 구조/방치 소문 → 기사단장 → 마물사냥꾼 → 광신도 → 부활 의식 → 마물의 왕 추적 순으로 연결한다.
8. 사건 원화 레이어/대사 비트/선택 UI를 붙인다.

완료되면 W120, W163, W170~W184의 **17개 🔴가 0개**가 되어야 한다.

### 2-B. 실제 규칙 차이를 고친다

1. **W094 저주 우선**
   - 웹 규칙을 정답으로 사용한다.
   - 같은 개체의 같은 눈금에서 저주가 하나라도 활성화되면 그 눈금의 다른 낙인 축복을 막는다.
2. **W086 완전 동률 행동 순서**
   - 완전 이식 원칙상 웹의 저장 가능한 RNG tie-break가 기본 목표다.
   - Godot stable-ID 방식을 유지하려면 반드시 `의도적 변경`으로 승인·기록해야 한다.
3. **W080 dracula**
   - 웹 46종 데이터 자체는 이미 완전히 일치한다.
   - Godot의 추가 `dracula`는 삭제할 필요가 자동으로 생기는 것이 아니다.
   - 정식 추가 콘텐츠로 유지할지, 웹 parity 대상 밖 확장으로 분리할지만 확정한다.
4. **W153 저장 revision**
   - 웹 IndexedDB의 revision 숫자를 그대로 복제하는 것이 목적이 아니다.
   - Godot 단일 프로세스 저장에서 tmp→rename + rollback + receipt가 같은 안전 목적을 충족하는지 강제종료/재실행 테스트로 확정한다.

### 2-C. 타이틀과 시각 차이를 마감한다

1. 타이틀 BGM을 확정한다.
   - 웹 `title-theme.mp3`를 옮기거나,
   - 새 Godot 타이틀용 음악을 정식 기준으로 지정한다.
2. 타이틀에서 Music/SFX 옵션 접근을 제공한다.
3. 웹 title video/logo/button 대신 현재 cemetery 레이어 타이틀을 최종 Godot 기준으로 기록한다.
4. `goblin-commoner` 15개, `soul-reaper` 16개 갱신 프레임을 실제 재생 확인한다.
5. 장소 배경 7종의 Godot 갱신본과 구름/상점/순찰/포획 UI 대체 연출을 실제 화면에서 승인한다.

## 완전 이식 후 회귀검증

기능을 옮긴 뒤 반드시 아래 흐름을 Godot만으로 확인한다.

```
새 게임
→ 인트로
→ 맵
→ 주사위 이동
→ 장소 기능
→ 덱 선택
→ 전투
→ 영구사망
→ 영혼 수확 / 보상
→ 집
→ 계승 / 순찰 조정
→ 다음 바퀴
→ 저장 종료
→ 이어하기
```

사건은 별도로:

```
공동묘지 아이
├─ 구한다 → 사건 전투 → 구조 소문 → 기사단장/마물사냥꾼 → 광신도 → 의식 → 추적
└─ 지나친다 → 방치 소문 → 현재 웹 구현 후속 조건
```

그리고 사건전투의 **승리/패배/지나감**, 덱 선택 도중 종료, 전투 도중 종료, 사건 복귀 도중 종료까지 각각 재실행한다.
