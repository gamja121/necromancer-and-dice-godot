## Godot 현재 구현과 차이 (코드 확인)
현행 `systems/place_actions.gd`:
- 거래대 자산을 사용하지 않고 `village.jpg`를 흐리게 표시한 뒤 카드·레이블을 바로 배치한다.
- 재물 카드 위치 (178,95), 크기 (144,210); 웹 거래대의 카드 슬롯에 정렬되지 않는다.
- 상인 제안 위치 (390 + i×145,140), 카드 (112,168); 웹의 오른쪽 거래대 상판/가로 스크롤 배치와 다르다.
- `offer_area`는 단순 Control이며 4/5개 상인 제안이 생기면 원본과 달리 고정 좌표로 뿌린다.
- 취소 (185,380), 상태 텍스트 (130,435), 닫기 (1100,26)는 원본 거래대 기준에 정렬되지 않는다.
- 반면 상점 기능 자체 `shop_offers()`, `shop_trade()`, 희생 마물 보호 및 카드 재생성/저장 처리는 존재한다. **규칙 수정 불필요.**

## 다음 구현 단계 — 하나의 화면만
1. 원본 거래대 PNG를 **원본 SHA를 기록하여 Godot 로컬 자산**으로 이식 (외부 URL 참조 금지).
2. `type == "village"` 한정으로 거래대 프레임/닫기/재물 슬롯/제안 카드/취소/상태를 웹 기준에 재배치.
3. 3/4/5개 제안의 한 줄 스크롤 지원. 아군 마물 손패는 스크롤/클릭/강조 유지.
4. 제단(`altar`) 및 점술가(`fortune-teller-camp`) 분기에는 UI 스타일과 좌표 변경을 전파하지 않음.
5. 골드 없이 마물을 재물로 교환, 마지막 마물 보호, 선택 2회 확인, 실제 1회 지급, 불러오기/취소/모바일 가로화면 확인.
6. 적용 전후 1280×720 실제 화면 캡처를 원본과 비교해 재물/카드/버튼 간 겹침 및 누락 0을 확인한 후 이 단계 완료 승인.

## 검증 방식
- **Trigger:** 마을 도착→마물 상점 버튼.
- **Information:** 보유 마물, 제안 수, 선택 카드, 교환 불가 사유, 거래 영구 소모 경고.
- **Interaction:** `RunSession.shop_offers/shop_trade`, 책/보유 목록, 보상·저장·인벤토리 갱신.
- **Visual:** 전용 상판 배경, 좌측 교환 슬롯, 우측 가로 스크롤 제안, 양피지 버튼·상태.
- **Persistence:** 교환 직후 기존 거래 기록 및 소모 마물 유지, 재시작 시 중복 지급 0.
