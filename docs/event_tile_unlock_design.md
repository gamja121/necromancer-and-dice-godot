# 사건 타일 기반 장소 발견·해금 설계 — 사용자 규칙, 2026-10-14

> **상태: 기획 확정(우선순위와 발견 경로) / 세부 수치·실제 게임 구현 미완료.**
> 사용자는 해금 가능한 타일을 **사건 타일**에서 발견하도록 정했다. 기존 조건부 사건·스토리가 최우선이며, **현재 시점에 발생할 수 있는 기존 사건이 없는 경우에만** 신규 장소 발견을 대신 진행한다.
> 예시 대사: **"언덕을 발견했다."** 발견한 타일이 집의 편성 화면에서 사용 가능해지거나 보드 위 길 타일이 해당 타일로 변환되는 연출을 원한다.
> AI는 이 신규 기획을 이전의 '첫 바퀴만 돌면 숙영/묘지가 자동 해금' 규칙과 혼동하지 않는다.

## 1. 필수 우선순위와 단일 결과

1. 실제 주사위/경로 이동으로 **사건 타일에 도착**한 경우에만 처리한다. 타일 미리보기 클릭, 저장 복원 중 화면 재구성, 이벤트창 복귀는 새 발견을 일으키지 않는다.
2. 기존 `map.gd:show_tile`의 기존 사건 체인(묘지 아이·마을 소문·기사단장·마물 사냥꾼·광신도 소문·제단·전이문·왕 추적/재개)과 현재 미완료 사건 복귀가 **항상 우선**이다. 해당 사건의 기존 `can_enter`, 단계·오염도·선행 플래그·선택/완료 가드를 유지한다. 기본 스토리 순서를 재편하지 않는다.
3. **모든 기존 사건 판정이 불충족**이고 이 방문에서 시작/재개/결과표시해야 할 사건이 없을 때만 장소 발견 후보를 검사한다.
4. 해금되지 않은 장소가 있으면 **단 한 종류만** 발견하여 "○○을 발견했다" 메시지와 타일 이미지를 보여준다. 발견 상태를 원정에 먼저 안전하게 저장한 뒤 연출한다. 저장 실패 시 지급된 것으로 표시하지 않고 재시도 가능하게 한다.
5. 발견할 장소가 없는 경우의 반복 이벤트는 별도 기획으로 남긴다. 임의의 신작 스토리·보상을 지급하거나 해금 반복을 만들지 않는다.
6. 기존 사건 `begin` 호출이 **실패**한 경우는 '사건이 없었다'와 같지 않다. 실패/저장 오류를 안내하고 발견 이벤트로 우회하지 않는다.

## 2. 발견과 배치는 서로 다른 상태

- **발견(해금)**: 사건 타일에서 일어난다. 예: "언덕을 발견했다." 발견 자체는 장소의 잠금을 풀며, 영속 저장한다.
- **타일 편성**: 집의 기존 '다음 바퀴 · 타일 편성'에서 발견한 종류만 추가 선택할 수 있는 방식이 안전한 1차 구현안이다. 이미 구성된 보드 24칸을 예고 없이 바꾸지 않는다.
- **시각적 변환**: 집에서 다음 보드로 나갈 때 일반 길 타일이 해금된 종류로 바뀌는 시각 연출을 적용할 수 있다. **즉시 현재 보드 변환**은 대안으로 남겨 두되, 실제 이동 중 타일 변경·이벤트 소멸·이동 경로 무결성 문제 때문에 사용자 최종 선택 없이는 도입하지 않는다.
- **불변 타일**: 집(인덱스15), 마을(8), 점술가(0), 사건/스토리 중인 타일, 보스 고정 칸(조건 충족 시), 늪용 예약 길 2칸은 임의로 교체하지 않는다. 보드 길이 24칸과 주사위 이동 로직을 유지한다.
- **중복 방지**: `event_flags` 같은 영속 상태에 장소별 `unlocked`를 구분하고, 사건 당 단 한 번의 발견 영수증(이벤트 ID/방문 ID)을 사용한다. 발견 후 원정 저장/재시작/맵 재배치 중 잠금이 다시 걸려서는 안 된다.
- **발견 대상 예시**: 언덕(`forest`), 숙영(`rest`), 공동묘지(`graveyard`), 세계수(`unknown`), 제단(`altar`) 등. **이름, 첫 발견 순서, 편성 슬롯을 차지할지, 종류별 배치 개수, 자동 고정 배치인지 등은 타일별로 최종 미정**이다. 예시 순서를 실제 드롭 테이블로 하드코딩하지 않는다.
- 사건 이벤트는 보드에서 사라지지 않는 별도 촉발 장소로 보존한다. 발견마다 사건 타일을 없애고 되돌리는 방식으로 구현하지 않는다.

## 3. 현재 원본의 실제 구현과 충돌 (적용 시 함께 수정해야 함)

- `map.gd:show_tile`: 기존 스토리 판정 순서는 구현되어 있음. 조건 불충족 시 신규 장소 발견 단계는 **없음**.
- `systems/map_state.gd:COUNTS`: 초기 맵에 `forest=1`이 기본 생성됨. 따라서 '처음 사건에서 언덕을 발견'하는 구조로 바꾸려면 시작 시 언덕이 보이는 상태와 **발견 후 배치 시점**을 함께 바로잡아야 함.
- `systems/map_state.gd:generate`: 묘지는 `laps>=1`이면 1칸 자동 배치함. 새 사건 발견 기획과 상충함.
- `systems/run_session.gd:rest_unlock_allowed` 및 `unlock_rest_tile`: 숙영은 첫 완주 후 집에서 명시적으로 해금하는 **현재 게임 코드**임. 새 사건 해금 기획에 따라 전환하는 경우 이 조건은 교체 또는 이전 저장 호환 처리 필요.
- `systems/route_plan.gd`: 선택 가능 종류는 `monster`/ `rest` 두 개뿐이고 `OPTIONAL_CAPACITY=6`, `REST_LIMIT=3`, 예약 길 2개. 다른 장소 해금을 도입하면 편성 선택·배치 제한·저장 검증을 함께 확장해야 함.
- `systems/map_state.gd:snapshot/restore`: 장소별 발견/해금 상태를 정규화·검증하지 않는 현행 스키마에 신규 영속 상태 추가 필요. 이전 `user://map_run_v1.json`을 파괴하지 않는 기본값/마이그레이션 필요.
- 모든 구현은 최신 `AGENTS.md`와 기존 보스 오염도 20/40/60 단계별 보스 기획을 보존해야 한다.

## 4. 제안되는 UX (콘텐츠나 아트 확정이 아님)

1. 사건 타일 방문 → **해당 조건의 기존 사건이 있으면 원래 사건**.
2. 없다면 짧은 발견 대사 **"언덕을 발견했다."**와 해당 타일 아이콘. 새 장소 추가 사실을 게임에 저장.
3. 집에서 타일 편성 화면을 열면 **언덕이 사용 가능**해진 것을 표시. 선택한 수량/배치 제한에 따라 예약한 길을 제외한 일반 길 중에서 다음 지도에 배치.
4. 출발 시 기존 구름/타일 교체 연출 속에서 길 타일 → 해당 장소 타일로 변화. 새 맵 상태를 저장하고 기존 맵 셔플 보장 사항을 지킨다.

## 5. 검증 기준 / 5원칙

- **Trigger**: 실제 사건 타일 도착 + 기존 사건 모두 비적격 + 미해금 장소 보유.
- **Information**: 현재 사건 스토리 상태, 오염도 조건, 방문 중복 키, 해금 목록, 선택 가능한 슬롯/길 수.
- **Interaction**: `map.gd` 우선순위 → `RunSession` 원정 영속 저장 → 집 `ExplorationActions` 편성 → `MapState` 다음 맵 생성.
- **Visual change**: 기존 사건 UI 우선, 아니면 발견 텍스트/타일 아이콘 표시, 집의 잠금 표시 해제, 다음 맵에서 길이 새 장소 타일로 바뀜.
- **Memory**: 해금/발견이 저장 복원·맵 셔플을 통과하고 이중 지급이 없음. 실패 저장 시 이전 상태 복구.

**필수 회귀 검사**: 스토리 조건 충족 시 발견 이벤트 절대 미발생, 조건 불충족 시 한 번만 발견, 미리보기나 저장 복원만으로 해금되지 않음, 신규 발견 상태가 저장 실패 시 롤백, 기존 이벤트 스토리/전투 복귀 정상, 집 고정 위치/보스/예약 길/24칸 유지, 구형 저장 파일 무손상, 기존 첫 바퀴 숙영/묘지 자동 해금과 새 규칙 간 충돌 해소.

## 6. 아직 열려 있는 디자인 결정

- 장소별 해금 순서와 대상으로 확정할 타일 목록.
- 사건 발견 즉시 현재 보드에 타일을 보여줄지, **집에서 편성 후 다음 지도에 배치**하는 것으로 확정할지(권장안: 후자).
- 발견할 신규 타일이 모두 소진된 뒤 사건 타일에서 무엇을 보여줄지.
- 종류별 타일 편성 최대 수량과 필수 자동 배치 여부.

현재 문서는 **기획 기록**이며 Godot 런타임 구현 완료를 뜻하지 않는다.
