## 보스 발생 조건 — 2026-10-14 사용자 재확정

**확정 기획:** 보스는 **오염도 20에서 1단계, 40에서 2단계, 60에서 3단계**, 그리고 **그 이후 최종 보스**가 별도 단계로 등장한다. 이 숫자는 **완주한 바퀴 수가 아니라 오염도**다. '20·40·60바퀴마다 보스'와 '60바퀴 최종 보스'라는 과거 설명의 **바퀴 기준만 폐기**되었다. '20·40·60 오염도에 단계별 보스가 나온다'는 구상을 폐기한 것이 아니다.

| 단계 | 보스 등장 기준 | 현재 상태 |
| --- | --- | --- |
| 1단계 보스 | 오염도 20 | 보스 타일 하나를 표시하는 기준만 구현됨 |
| 2단계 보스 | 오염도 40 | 전용 단계 구분·보스 선택·처치 기록 미구현 |
| 3단계 보스 | 오염도 60 | 전용 단계 구분·보스 선택·처치 기록 미구현 |
| 최종 보스 | 이후 최종 단계, **정확한 오염도 미확정** | 별도 진행·보스 구현 미확인/미완성 |

**현재 실행 코드와의 차이:** `systems/map_state.gd`의 `BOSS_CONTAMINATION = 20`은 오염도 20부터 모든 이후 단계에서 기존 `boss` 타일 한 개(index 23)를 보이게 한다. `systems/run_session.gd`는 오염도 20 최초 통과 시 그 타일을 갱신한다. 이 로직만으로는 오염도 40/60에 새로운 단계 보스를 출현시키거나 최종 보스전을 실행하지 못한다. 기존 한 번의 보스 타일이 다음 맵에서 다시 생성될 수 있는 것과 **단계별 보스 진행/격파 관리**는 별개다.

`LAP_CONTAMINATION_GAIN = 7`은 집에서 완주 후 나갈 때 오염도를 올리는 값이다. 바퀴 자체는 보스의 직접 트리거가 아니다. 이전 기록의 '오염도 80에 보스 한 번'은 현행 **다단계 보스 기획과 다르며**, 80을 최종 보스 조건으로 확정한 근거는 없다.

**미결정 사항:** 최종 보스 등장 수치, 단계별 보스 정체·전투 내용, 최초 격파 후 해당 보스의 재출현 가능 여부, 오염도 감소/재상승 시 처리, 진행 저장·복원, 최종 전투 종료 조건. 정해지기 전에는 임의의 최종 보스 수치나 보상·반복 규칙을 구현하지 않는다.

**5원칙 점검:** Trigger=오염도 20/40/60 경계 및 최종 조건, Information=현재 오염도·단계별 격파 상태·이전 최고 도달 단계, Interaction=맵·전투·원정 진행 관리, Visual=해당 단계 보스 타일/정보와 전투 화면, State=단계 해금·격파/진행 여부 영속 저장(향후 설계 대상). 현재 문서 정정은 런타임/저장 포맷을 변경하지 않는다.

## 전투 덱 선택
GitHub main의 v2-map-practice.js renderDeckSelection/toggleDeckUnit 및 원본 CSS 배치를 확인하여 이식. 미처치 마물 조우 시 선택을 비운 원본 보드 창을 열고 보유 개체 ID 기준 1~4명을 선택한다. 클릭 순서대로 왼쪽 슬롯에 배치하며 재클릭으로 해제. 인원별 피격 확률 100 / 35·65 / 20·33·47 / 15·20·27·38을 표시. 카드 0장이면 전투 시작 불가. 보드 내려오기·손패 올라오기 연출을 적용. 선택한 개체의 순서·현재 HP·낙인을 기존 전장에 전달하며 미출전 개체는 유지한다. 빈 보유 상태는 창 대신 안내한다.
새 테스트 UI/코드는 추가하지 않았다. Godot 편집기 불러오기 및 기본 시작 실행에서 오류가 없었다. Windows 화면 캡처 도구 시간 초과로 실제 카드 클릭·배치의 시각 확인은 미완료.
